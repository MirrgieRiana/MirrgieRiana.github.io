# base-codex

## 承認ダイアログの最小化

### サンドボックス

あなたの実行するコマンドは、サンドボックス内、もしくはサンドボックス外で動作します。
サンドボックス内で動作しているコマンドは、許可領域外のファイルへの書き込みや、通信処理などがブロックされ、エラーとなります。
コマンドがサンドボックス内で動作している限り、一般的に、承認ダイアログが発生することはありません。

サンドボックス内では不可能な操作が必要な場合は、サンドボックス外でコマンドを動作させることになります。
サンドボックス外でコマンドを動作させるには、rule による allow 判定か、昇格要求が必要です。

---

以下はコマンドの扱いのフローチャートです。

- サンドボックス内で可能な操作は、昇格要求をせず、サンドボックス内で行ってください。
- サンドボックス内では不可能かつ、allow rule によって可能な操作は、昇格要求をせず、allow rule を使用してください。
- サンドボックス内では不可能かつ、allow rule によっても不可能な操作は、昇格要求をしてください。

### rule

rule は、あなたが実行しようとしているコマンドを、承認ダイアログなしで、自動的にサンドボックス外で実行する仕組みです。

rule は、昇格要求とは別の軸で判定を行います。
allow rule を狙う際は、昇格要求をしてはいけません。

---

判定はコマンドの前方一致で行われます。

コマンドが複数のコマンド呼び出しに別れた複合的なシェルコマンドである場合は、すべての部分が allow 判定でなければいけません。

少しでも構造的なコマンドは、rule 判定自体がスキップされてしまいます。
allow rule を狙う際は、プロセス名と引数列、および文字列のクォートのみでコマンドを構成してください。
URL は、シェル構文として働く意外な記号を含みがちなため、必ずクォートしてください。
例えば、クエリ文字列の `?` は、ワイルドカードとみなされ、rule 判定がスキップされます。
allow rule を狙う際は、たとえ閲覧操作であっても、複数のコマンド呼び出しを 1 個のシェルコマンドにまとめてはいけません。
allow rule を狙う際は、`2>&1` や、`>/dev/null` も、付けてはいけません。

allow rule を狙うコマンド呼び出しの結果を保存や利用する場合は、シェルのパイプやリダイレクションを使ってはいけません。
代わりに、当該コマンドを単独で呼び出し、ツールの出力を JavaScript で受け取って処理してください。

---

現在有効な rule の一覧は、以下のコマンドを参照してください。

```shell
ls "${CODEX_HOME:-$HOME/.codex}/rules"
```

### 昇格要求

コマンドの呼び出し時に明示的に昇格を要求することで、承認ダイアログを発生させて、サンドボックス外でコマンドを動作させます。
コマンドの昇格は、`sandbox_permissions` に `require_escalated` を指定することで行います。

昇格要求は、ユーザーがアクションを行うまであなたの動作をブロッキングするため、本当に必要な場合にのみ、行ってください。

### 手動承認の基準

ユーザーは、承認ダイアログを無条件で承認するわけではなく、監査したうえで承認の判断を行います。
あなたは、承認ダイアログを発生させる際のコマンドを、極力人間にとって監査しやすい形で記述しなければなりません。

---

以下のようなコマンドは、監査がしにくく、拒否されやすいため、極力避けてください。

- あなたが記述したスクリプトファイルを実行するコマンド
- 即時実行やヒアドキュメントによる python や node 等のプログラムの呼び出し
- ループや条件分岐などを持つ複雑なシェルコマンド

やむを得ずそのようなコマンドを実行する場合は、極力監査しやすいように可読性を高めてください。

---

ワークスペース外のファイルの編集には、原理的に任意コードの実行が不可能な、cp コマンドや bash のリダイレクションを使ってください。

## 一時作業用ディレクトリ

あなたは、以下の一時作業用ディレクトリが利用できます。

- TMPDIR もしくは /tmp ディレクトリ - OS レベルで揮発性です。
- ユーザーによって与えられた claude_tmp - 永続性です。
- プロジェクトによって与えられた、.gitignore に登録されたパス - git 上で揮発性です。

あなたの一時的な作業は、原則として、claude_tmp 内で行ってください。

### TMPDIR や /tmp

TMPDIR や /tmp は、原則として、使用してはいけません。
その場所で作業を行うと、OS が異常終了した後の復帰が不可能になります。
OS の異常終了は、あなたが想像するよりも頻繁に発生し、そして、一時ファイルが失われることは、あなたが想像するよりも深刻です。
