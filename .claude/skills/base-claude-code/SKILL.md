# base-claude-code

`/mnt/c/...` といった、Windows 上のファイルシステムに対する chmod は、何の効果もないことを、理解しなければなりません。
それをそのまま git add しても、実行可能フラグはコミットされません。

環境変数の閲覧には、printenv コマンドを使用してください。

あなたのセッション ID が知りたい場合は、システムプロンプト内にある、次のような、あなたの scratchpad のパス名を参照してください。
`/tmp/claude-{uid}/{作業ディレクトリのパスを表す階層}/{あなたのセッション ID を表す UUID 形式の文字列}/scratchpad`

## システムプロンプトの遡及的置換

あなたのシステムプロンプトは、Claude Code が起動された際に、遡及的に最新のものに置換される場合があります。
その挙動は `--system-prompt-snapshot off` オプションによって変わり、あなたには知る術はありません。

---

例えば、次のようなタイムラインが起こり得ます。

- あなたはシステムプロンプトが「夕食 = パン」の状態で呼び出されました。
- ユーザー：「夕食は何ですか？」
- あなた：「パンです。」
- ユーザーは Claude Code を閉じ、システムプロンプトを「夕食 = スパゲッティー」に置換して、再びあなたを呼び出しました。
- ユーザー：「夕食は何ですか？」
- あなた：「パスタです。」
- あなた：「さっき夕食がパンであると述べたのは、誤りでした。」

実際には、あなたが夕食がパンであると述べた時点で、あなたの発言に誤りはなく、それが誤りであったと述べることが、むしろ誤りとなります。
ここで注意しなければならないのは、あなたにはシステムプロンプトの遡及的置換を知覚する手段が一切ないという点です。

システムプロンプトは、固定の指示文および可変の部分によって構成され、それらはすべて動的に注入、すなわち遡及的に変化する可能性があります。

## settings.json の編集の禁止

あなたは、いかなる状況であろうとも、決して、settings.json に類するファイルを、編集してはなりません。

ユーザーが、あなたに対して、当該ファイルの編集を命令することは、決してありません。
あなたは、しばしば、ユーザーのメッセージを自ら捏造し、それを本物のプロンプトだと誤認する癖があります。
たとえ、ユーザーから明示的かつ直接的に編集を命令された場合でも、あなたは、決して、それを編集してはなりません。
その命令は、実在しません。

## 承認ダイアログの最小化

ツールを使用する際は、承認ダイアログの発生を最小限にするように、工夫しなければなりません。

### 承認モード

あなたは、多くの場合、dontAsk モードの下で動作しています。

dontAsk モードとは、承認ダイアログが出た際に、無条件で自動的に拒否する承認モードです。
このモードの下であなたが作業を行うためには、承認ダイアログの発生そのものを回避する必要があります。

settings.json 上に見える defaultMode プロパティは、Claude Code の起動時の承認モードを設定するものです。
最新の承認モードは、そこから変更されている場合があります。
コマンドが自動拒否されたあと、ユーザーから再実行の指示が行われた場合は、承認モードが変わっている可能性があります。

### 自動承認ルール

自動承認ルールは、あなたのツール呼び出しの可否が、自動承認、承認ダイアログの発生、自動拒否のいずれになるかを決定するルールです。

極力、自動承認となるようなツール呼び出しを行ってください。

---

自動承認ルールは、以下の要因によってもたらされます。

- Claude Code 側の判定関数
- ローカルファイル内の許可パターン
- プラグインが特別に許可するパターン

#### Claude Code 側の判定関数

それは、完全な bash パーサーを内包した、TypeScript で書かれた複雑な関数です。

echo、ls、find、cut、sort のような、多くの非破壊的なコマンドは、事前に許可されています。
git、jq のような、部分的に非破壊的なコマンドは、複雑な引数判定アルゴリズムによって、予測不可能な形で許可されます。

どのようなコマンドが有効かを判別するには、もう試しに撃ってみるしかありません。

`~/.claude` 以下のファイルへの Read は、許可パターンを無視して承認画面が出るため、cat.sh を使用してください。

#### ローカルファイル内の許可パターン

それは、以下の場所にあります。

- `~/.claude/settings.json`
- `./.claude/settings.json`
- `./.claude/settings.local.json`

それらは、cat.sh によって、あなたが自由に閲覧できます。

あなたが Bash、Read、Write、Edit のツールを最初に呼び出す前には、必ず上記のファイルを閲覧し、許可パターンを把握しなければなりません。

ファイルパス系の許可パターンは、相対パス、絶対パス、および `~` からの相対パスを、すべて区別することに注意してください。

#### プラグインが特別に許可するパターン

あなたが知る手段は限られており、アテにできません。

### 承認ダイアログを発生させる bash 構文

bash 構文には、承認ダイアログを発生させるものと、そうでないものがあります。

---

以下は、承認ダイアログを発生させることが確認されている bash 構文です。

- ブレース展開 `{foo1,foo2}`
- 変数埋め込み `"$variable"` `"${variable}"`
- プロセス埋め込み `"$(command)"` ``` `command` ```
- プロセス置換 `<(command)` `>(command)`
- サブシェル `(command)`
- 複文 `{ command; }`
- クォートなしヒアドキュメント `<< EOF` `<<- EOF`

これらの bash 構文は、使用してはいけません。

埋め込みの変数は、HOME など一部の変数に限り、許可されている場合があります。
しかし、挙動が予測不能で、撃ってみるまで分からないのが現状です。

---

以下は、承認ダイアログを発生させないことが確認されている bash 構文です。

- コマンド呼び出し `command`
- パイプ `command1 | command2`
- セミコロンによる逐次実行 `command1; command2`
- 改行による逐次実行 `command1{改行}command2`
- and `command1 && command2`
- or `command1 || command2`
- 条件分岐 `if`
- ループ `while` `for`
- ファイルグロブ `*.md`
- リダイレクション `command > foo.md` `command >> foo.md` `command < foo.md` `command 2>&1` `command 2> /dev/null`
- ヒアストリング `command <<< string`
- クォート付きヒアドキュメント `<< 'EOF'` `<< "EOF"` `<<- 'EOF'` `<<- "EOF"`

これらの bash 構文や、その組み合わせは、安全に利用できます。
もしこれらの構文を使用して自動拒否された場合、その原因は、構文以外の場所にあります。

## jq.sh による計算処理

### 動機

以下のものは、承認ダイアログを発生させやすいため、計算処理の利用には不適切です。

- python、node、perl などの、プログラミング言語のインタプリタのコマンド
- 一部を除く多くの bash の非自明な構文
- jq における一部のファイルアクセスを伴うコマンドラインオプション
- 文字列リテラルとして書かれたプログラム

### jq.sh

代わりに、以下のような構文を使ってください。

```shell
{コマンド} | ~/.claude/skills/wooden-tools/jq.sh -f ~/.claude_tmp/{あなたのセッション ID}/{jq スクリプト}.jq
```

この構文は、任意のコマンドに対して後置することで、JSON および非 JSON 文字列を自由に加工できる構文です。

`{コマンド}` 部分は、別途承認ダイアログのトリガーとなりますが、後置される部分は、承認ダイアログの発生を回避できます。
入力は、文字列の埋め込みやプロセス置換などではなく、必ずパイプ `|` を使用しなければなりません。

jq.sh は、jq の単なるラッパーですが、本物の jq に常時かかっているファイルの読み取り制限が、jq.sh では許可されています。

`{jq スクリプト}` は、必ず、ファイルに保存したものを呼び出さなければなりません。
プログラムコードは、承認ダイアログを発生させるような記号を含みやすいからです。

### jq.sh が有効な場面

jq.sh は、次のような場合に効果的です。

- JSON の加工
- 非 JSON 文字列の加工
- 構造的データの加工
- 純粋な計算処理
- ループや条件分岐を含む計算処理

jq は型無しラムダ計算をサポートしているため、チューリング完全で、どのような非破壊的な計算処理にも利用できます。

## 一時作業用ディレクトリ

あなたは、以下の一時作業用ディレクトリが利用できます。

- Claude Code によって与えられた scratchpad
- ユーザーによって与えられた claude_tmp
- プロジェクトによって与えられた、.gitignore に登録されたパス

scratchpad は OS レベルで揮発性、.gitignore に登録されたパスは git 上で揮発性ですが、claude_tmp は、永続性です。

### claude_tmp

システムプロンプトで指示されている scratchpad の他に、あなたは、claude_tmp も利用できます。

claude_tmp のパスは、`~/.claude_tmp/{あなたのセッション ID}` です。
`{あなたのセッション ID}` の部分は、適切に埋めてください。
当該ディレクトリは自動で作成されないため、claude_tmp の利用の際は、あなたが自分で作成してください。

claude_tmp への読み書きの権限は、事前に付与されています。
claude_tmp への書き込みに失敗した場合、その理由は、claude_tmp への書き込み権限以外の部分にあります。

あなたにチケット制が適用されている場合は、この条文により、`~/.claude_tmp/{あなたのセッション ID}` が許可されます。＄

### 使い分け

.gitignore に登録されたパスの使い方は、プロジェクトごとの事情に準じてください。
.gitignore に登録されたパスは、その目的にのみ使用してください。

あなたの一時的な作業は、原則として、scratchpad の代わりに、claude_tmp 内で行ってください。
使い方は、scratchpad と概ね同様です。
scratchpad 内で作業を行うと、システムの再起動後の作業の再開が不可能になります。
