# コーディング規約

プログラムの編集において、検証すべき点や、どのようなパターンを避けるべきかについての雑多なまとめです。

## 設計

特定の実装専用というわけではない共有の部分の上に、特定の実装を区別する分岐が含まれているのは、エレガントではありません。

特定の実装の上に、その場しのぎな処理を足すよりも、共通の部分の実装を一般化し、綺麗な実装をする方が、望ましいです。

各変更が、本来の目的を達成するうえで、不必要なリファクタリングになっていないか。

各変更が、その目的を達成する上で必要な前提を正しく実装せず、前提を欠いたまま、その場しのぎの実装をしてしまっていないか。

## 網羅性

ラッパー、アダプター、プロキシ、キャッシュ等、何かを包むオブジェクトを追加や変更したとき、すべての参照が包んだものへ再配線されているか。

## フロー

ガード、エラー判定、検証、テスト等が、消えたか、動作条件が狭められた場合、それが実在の場面をカバーしなくなったか。

削除や置換された各行について、それが守っていた不変条件や振る舞いが、新しいコードでも再び確立されているか。
