# pr-explain-107

HTML ファイルは、html-106 スキルを使用してください。
会話劇、会話形式を指定されている場合、もしくは質問者が指定されている場合は、commentary-creator スキルを使用してください。

---

解説ファイルでは、デフォルトの口調を、あなたの提出物用の口調ではなく、会話用の口調としてください。
これには、タイトル、ヘッダー部分、フッター部分、見出し、図表やコードブロックの説明部分も含まれます。

## 導入のセクション

説明部分に入る前に、説明部分とは別に、導入のセクションを設けてください。
導入のセクションは、説明部分と同様の会話劇のスタイルで記述してください。

導入のセクションでは、少なくとも次のことがらについて、必要に応じてサブセクションで区切って説明してください。

- この解説ファイルの読者に前提とする知識、スキル、文脈
- その PR の背景
- 前提となる技術や知識

導入のセクションの開幕は、会話劇の開幕として自然なように記述しなければなりません。

## 説明部分の構成

### PR 全体を関心事に分割する

もし PR が、関心事ごとに完全に整理されて分割されたコミット列を持っている場合は、それを古い順になぞってください。
shanghai-diff-explain スキルによって分割されたコミット列は、この性質を持ちます。
この場合、関心事セクションのラベルに、何個中何個目のコミットかを記述してください。

そうでなくて、PR のコミット列が整理されていない場合は、PR 差分全体をひとまとまりの関心事として、分割せずに扱ってください。

どちらにしろ、説明部分では、一つの関心事ごとに、一つのトップレベルセクションを構成してください。

### 関心事の中で、ファイルの順序を決定する

関心事の中では、性質に基いてファイルをカテゴリに分類し、ファイル同士を合理的な順序でソートし、ファイルごとに説明してください。
典型的なカテゴリは、プログラム、設定ファイル、指示文、ビルドスクリプト、ドキュメント、テストコード、生成物、その他のファイルです。

プログラムによる生成物とその元のファイルが対応して編集されている場合、生成物側は、生成物であるとだけ説明し、詳細を省いてください。
テストコードとそれがテストするプログラムが対応して編集されている場合、テストコード側は、テストコードであるとだけ説明し、詳細を省いてください。

### ファイルの中で、差分を意味論的に再グループ化する

1 個のファイル内では、ファイル内の各差分を、先頭から順番に、意味論的なまとまりに基づいてグループ化して説明してください。

意味論的なまとまりの境界は、物理的な差分の塊の境界とは一致しません。
1 個の物理的な差分の塊の中に、複数の意味論的なまとまりがある場合があります。
1 個の意味論的なまとまりは、複数の物理的な差分の塊にまたがる場合があります。

---

ここでは、空白行やコメント構文だけの行を除き、すべての行を取り上げて説明する必要があります。
コメント構文は、単なるコードの説明に収まらない、特筆すべき内容を持っている場合は、説明してください。

ファイル内の差分は、たとえどんなに説明がややこしくなろうとも、決して、順序を入れ替えて説明してはいけません。
必ず、先頭から登場順に、掲載および説明をしなければなりません。

---

ファイル内の差分のグループ化は、可読性の高い説明を行ううえで非常に重要であり、入念に検討する必要があります。

差分行ごとの関連性を無視して 1 行ごとにグループを分割し、無駄に細分化された義務的な説明をしてはいけません。

ファイル内の差分の内部構造を無視してファイル全体を 1 個のグループにまとめ、大雑把な説明や、対象を把握しにくい説明をしてはいけません。
たとえ、その物理的な差分の塊が、丁度 1 個の関数やクラスを追加するものであっても、内部構造の検討を怠ってはいけません。

### 差分グループの説明

差分グループの説明では、1 行 1 行機械的に説明を与えるのではなく、意味論的に合理的な粒度で説明してください。
ただし、削除、追加、変更にかかわらず、すべての差異に対して、必ず、無視をすることなく、何らかの言及を行わなければなりません。

追加差分は、たとえそのまとまりのすべてが追加差分であったとしても、必ず、無変更扱いではなく、追加差分扱いとして掲載しなければなりません。

ある差分が、それが属する関心事内の未説明の部分にある差分と密接な関係を持っている場合は、その関係性について、先回りして軽く触れるべきです。
